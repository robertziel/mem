### Behavioral Story Bank — Common Questions & Story Mapping

**Definition:** the **story bank** is the foundation of behavioral interview prep. Eight canonical story categories cover virtually every behavioral question. Prepare **8–10 versatile stories** in STAR format — one strong story can answer 3–4 different questions by emphasizing different beats.

**The 8 canonical story categories:**

| # | Category | Common questions |
|---|---|---|
| 1 | **Conflict / Disagreement** | Disagreed with manager, teammate friction, cross-team |
| 2 | **Failure / Mistake** | Biggest mistake, prod incident, missed deadline |
| 3 | **Leadership / Initiative** | Led project, mentored, drove a practice |
| 4 | **Ambiguity / Autonomy** | Unclear requirements, decision with incomplete info |
| 5 | **Achievement / Impact** | Proudest accomplishment, most impactful project |
| 6 | **Collaboration / Teamwork** | Cross-team work, helped struggling teammate |
| 7 | **Customer / User Focus** | Went above for user, user-first decision |
| 8 | **Growth / Learning** | Learned new tech fast, adapted to change |

**STAR template — structure each story this way:**

| Beat | What goes here |
|---|---|
| **S — Situation** | Context: company, team, time, what was happening |
| **T — Task** | Your role / what was at stake |
| **A — Action** | Specific things YOU did (not "we") |
| **R — Result** | Quantified outcome + what you learned |

**Story versatility — one story → many questions:**

Example: "Payment service migration incident":

| Question type | What you emphasize |
|---|---|
| **Failure** | What went wrong; my role in the cause |
| **Leadership** | I led the recovery + postmortem |
| **Learning** | What I changed in my behavior afterward |
| **Ambiguity** | Scope was unclear; I defined the boundaries |
| **Collaboration** | How I worked with SRE, product, support |
| **Customer focus** | How users were impacted; comms I led |

> **Prepare 4–6 versatile stories**, not 20 weak ones. Each story should cover at least 3 of the 8 categories.

**Story selection criteria — what makes a strong one:**

| Criterion | Detail |
|---|---|
| **Recent** | Within 1–2 years (or significant if older) |
| **Quantified** | Time saved, $ saved, users impacted, incidents reduced |
| **Specific** | Real names, dates, technologies (anonymized if needed) |
| **You-driven** | Specific things YOU did, not "we" |
| **Outcome-clear** | What changed, what stuck |
| **Honest** | Real challenges, not heroic fiction |
| **Lesson learned** | What you'd do differently |

**Story-bank preparation checklist:**

| Item | Detail |
|---|---|
| 8–10 stories written in STAR | Cover all 8 categories |
| Each story tagged with which questions it answers | Quick recall |
| Each story tagged with company values (if known) | Tailor for target |
| Quantified results | Numbers > vague claims |
| Practiced **out loud** | Not just read |
| Timed to 2–3 min | Don't ramble |
| Prepared follow-ups | "What would you do differently?" / "What did you learn?" |
| Ready for "tell me about yourself" | Career arc story |
| Ready for company-specific values | Amazon LP, Google Googleyness, Meta values |

**Common follow-ups — prepare answers:**

| Follow-up | What it tests |
|---|---|
| "What did you learn?" | Growth mindset |
| "What would you do differently?" | Self-awareness |
| "How did your manager react?" | Relationship management |
| "What was the hardest part?" | Challenge depth |
| "What was your role specifically?" | I vs we |
| "How did you measure success?" | Outcome focus |
| "What if it had failed?" | Risk thinking |
| "Would you do it the same way again?" | Reflection |

**Anti-patterns — what NOT to say:**

| Anti-pattern | Effect |
|---|---|
| "We" everywhere | Unclear what YOU did |
| Blaming others | Lacks ownership |
| No specific outcome | Sounds invented |
| 5-minute setup before action | Boring |
| Heroic tone | "I single-handedly saved..." |
| "I never make mistakes" | Lacks humility |
| "I would have done it differently" | But did you? |
| Vague metrics ("a lot", "many") | No credibility |
| Only success stories | Show learning from failure |

**Tailoring to company values:**

| Company | Key values |
|---|---|
| **Amazon** | Customer obsession, ownership, dive deep, frugality (16 LPs) |
| **Google** | Googleyness (humility, ambiguity, collaboration), leadership |
| **Meta** | Move fast, build awesome things, focus on impact |
| **Apple** | Quality, attention to detail, user experience |
| **Netflix** | Freedom + responsibility, judgment, candor |
| **Microsoft** | Growth mindset, customer focus, diversity |

**Time budget — 2–3 minutes per story:**

| Beat | Time |
|---|---|
| Situation | 30s |
| Task | 15s |
| Action (the bulk) | 60–90s |
| Result | 30s |

**Strong opening / closing:**

| Opening | Closing |
|---|---|
| "About 18 months ago, I was leading the migration of..." | "...so the migration shipped two weeks ahead of schedule with zero incidents, and we've kept that pattern for every subsequent migration." |
| "There was a moment last quarter when..." | "...and I now use that retrospective format on every project." |

**Rule of thumb:** **Prepare 8–10 versatile stories**, each covering 3–4 categories. Use **STAR** with quantified outcomes. Practice **out loud** with a 2–3 minute timer. Have answers ready for the inevitable follow-ups: **"What did you learn?"** and **"What would you do differently?"** Tailor language to the **company's stated values** (Amazon LPs, Googleyness, Meta values). Specific names, dates, numbers beat vague heroics every time.
